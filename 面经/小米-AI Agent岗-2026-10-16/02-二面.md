# 二、二面

> 题量：4 题 ｜ 形式：系统设计 + 评测体系 + 线上问题排查，全部收束到小爱端云协同场景。

### 1. 设计小爱端云协同个人助理 Agent（查日程、天气、本地文件，多租户、SSE），讲架构 + 难点

**答**：分层架构。端侧层：轻量意图识别、本地记忆、弱网降级；会话层 Redis 保存会话与熔断计数；工具管理层管理天气、日程、本地文件工具；Agent 编排层 ReAct 规划，简单请求走 Workflow；LLM 层调用云端 MiLM，SSE 流式输出；隐私风控层保护本地数据；最后监控采集各项指标。

难点：弱网任务续跑、端云状态一致性、手机功耗、多租户隐私隔离、云端 token 成本控制。

### 2. Agent 评测有哪些指标，区分客观、主观指标？

**答**：客观指标：任务完成率、工具调用成功率、首 token 延迟、幻觉率。主观指标：用户满意度、回答有用性打分。客观指标做自动化回归，主观指标靠 A/B 测试。

### 3. 大量用户反馈 Agent 任务失败，排查与迭代思路？

**答**：第一，全链路 Trace 埋点，定位故障节点；第二，收集 badcase 归类；第三，判断根因是意图识别、工具描述、模型还是检索问题；第四，修复后小流量灰度上线，持续监控指标。

### 4. 小爱场景，Workflow 和 Agent 怎么混合选型？

**答**：简单高频任务，查天气、设置闹钟，走 Workflow，稳定低成本。复杂多步任务，行程规划、多文件查询交给 Agent。线上两者混合，减轻大模型压力。
