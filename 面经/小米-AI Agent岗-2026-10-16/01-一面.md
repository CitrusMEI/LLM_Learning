# 一、一面

> 题量：8 题 ｜ 形式：自我介绍与项目介绍，随后围绕 Agent 编排、RAG 检索、端云协同与多租户连续追问。

### 1. 自我介绍，介绍 Agent 项目，你负责哪些模块？

**答**：我做的是基于 LangGraph 的工具调用 Agent，搭配 RAG 知识库。我负责整体编排逻辑、混合检索、Redis 分布式熔断、上下文压缩模块。这个 Demo 可以自主规划任务、调用工具，处理多轮问答，规避死循环。

### 2. 讲 Agent 完整流程 ReAct 的 Thought / Action / Observation？

**答**：ReAct 是循环执行。Thought：模型思考，判断是否需要调用工具；Action：选定工具，输出参数；Observation：拿到工具返回结果，再次判断信息够不够。信息充足直接回答，不够继续循环，全程加熔断防止死循环。

### 3. LangGraph vs LangChain，Workflow 和 Agent 如何选型？

**答**：LangChain 以线性链式 Workflow 为主，原生缺少循环和状态持久化。LangGraph 是图编排，支持分支、循环、断点续跑，适合 ReAct。简单固定任务用 Workflow，稳定省 token；多步骤复杂任务用 Agent。线上一般混合架构。

### 4. Agent 死循环，单机熔断怎么做？分布式为什么不能内存计数？Redis 方案？

**答**：单机：内存计数，限制最大工具调用次数，检测重复调用就终止。分布式多实例内存互相隔离，重启扩容状态丢失，熔断失效。分布式用 Redis，sessionId 做 key 保存调用次数，设置 TTL；连续多次调用相同工具参数，直接判定死循环终止任务。

### 5. Embedding 输出向量维度，固定分块的缺点？

**答**：我项目里用的 Embedding 输出 768 维向量。固定分块容易把完整语义切断，破坏上下文；长文本还会出现 Lost-in-the-Middle 问题。我用语义分块 + 固定分块结合优化。

### 6. ANN 检索 HNSW 原理是什么？

**答**：HNSW 是多层有向图结构。上层粗粒度快速导航，下层做精准检索。优点召回速度快，检索质量高；搭配 PQ 量化压缩向量，降低内存开销。

### 7. 小爱端云协同 Agent 怎么设计？哪些任务放端侧、哪些上云端 MiLM？难点？

**答**：轻量意图识别、基础记忆、简单工具放在手机端，延迟低，保护隐私；复杂多步规划、长文档 RAG、深度推理交给云端 MiLM。难点：手机功耗内存受限，端模型需要量化；弱网下要处理会话同步、任务断点续跑。

### 8. Agent 多租户隔离怎么做，资源怎么隔离？

**答**：每个用户独立 sessionId，Redis 按 session 隔离会话；向量库按租户做索引隔离；工具层增加租户权限校验；并发限流，防止单个用户占用过多算力资源。
