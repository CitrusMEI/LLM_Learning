一一面8 题

自我介绍与项目介绍，随后围绕 Agent 编排、RAG 检索、端云协同与多租户连续追问。

  1. 自我介绍，介绍 Agent 项目，你负责哪些模块？

    答我做的是基于 LangGraph 的工具调用 Agent，搭配 RAG 知识库。我负责整体编排逻辑、混合检索、Redis 分布式熔断、上下文压缩模块。这个 Demo 可以自主规划任务、调用工具，处理多轮问答，规避死循环。

  2. 讲 Agent 完整流程 ReAct 的 Thought / Action / Observation？

    答ReAct 是循环执行。Thought：模型思考，判断是否需要调用工具；Action：选定工具，输出参数；Observation：拿到工具返回结果，再次判断信息够不够。信息充足直接回答，不够继续循环，全程加熔断防止死循环。

  3. LangGraph vs LangChain，Workflow 和 Agent 如何选型？

    答LangChain 以线性链式 Workflow 为主，原生缺少循环和状态持久化。LangGraph 是图编排，支持分支、循环、断点续跑，适合 ReAct。简单固定任务用 Workflow，稳定省 token；多步骤复杂任务用 Agent。线上一般混合架构。

  4. Agent 死循环，单机熔断怎么做？分布式为什么不能内存计数？Redis 方案？

    答单机：内存计数，限制最大工具调用次数，检测重复调用就终止。分布式多实例内存互相隔离，重启扩容状态丢失，熔断失效。分布式用 Redis，sessionId 做 key 保存调用次数，设置 TTL；连续多次调用相同工具参数，直接判定死循环终止任务。

  5. Embedding 输出向量维度，固定分块的缺点？

    答我项目里用的 Embedding 输出 768 维向量。固定分块容易把完整语义切断，破坏上下文；长文本还会出现 Lost-in-the-Middle 问题。我用语义分块 + 固定分块结合优化。

  6. ANN 检索 HNSW 原理是什么？

    答HNSW 是多层有向图结构。上层粗粒度快速导航，下层做精准检索。优点召回速度快，检索质量高；搭配 PQ 量化压缩向量，降低内存开销。

  7. 小爱端云协同 Agent 怎么设计？哪些任务放端侧、哪些上云端 MiLM？难点？

    答轻量意图识别、基础记忆、简单工具放在手机端，延迟低，保护隐私；复杂多步规划、长文档 RAG、深度推理交给云端 MiLM。难点：手机功耗内存受限，端模型需要量化；弱网下要处理会话同步、任务断点续跑。

  8. Agent 多租户隔离怎么做，资源怎么隔离？

    答每个用户独立 sessionId，Redis 按 session 隔离会话；向量库按租户做索引隔离；工具层增加租户权限校验；并发限流，防止单个用户占用过多算力资源。

二二面4 题

系统设计 + 评测体系 + 线上问题排查，全部收束到小爱端云协同场景。

  1. 设计小爱端云协同个人助理 Agent（查日程、天气、本地文件，多租户、SSE），讲架构 + 难点

    答分层架构。端侧层：轻量意图识别、本地记忆、弱网降级；会话层 Redis 保存会话与熔断计数；工具管理层管理天气、日程、本地文件工具；Agent 编排层 ReAct 规划，简单请求走 Workflow；LLM 层调用云端 MiLM，SSE 流式输出；隐私风控层保护本地数据；最后监控采集各项指标。难点：弱网任务续跑、端云状态一致性、手机功耗、多租户隐私隔离、云端 token 成本控制。

  2. Agent 评测有哪些指标，区分客观、主观指标？

    答客观指标：任务完成率、工具调用成功率、首 token 延迟、幻觉率。主观指标：用户满意度、回答有用性打分。客观指标做自动化回归，主观指标靠 A/B 测试。

  3. 大量用户反馈 Agent 任务失败，排查与迭代思路？

    答第一，全链路 Trace 埋点，定位故障节点；第二，收集 badcase 归类；第三，判断根因是意图识别、工具描述、模型还是检索问题；第四，修复后小流量灰度上线，持续监控指标。

  4. 小爱场景，Workflow 和 Agent 怎么混合选型？

    答简单高频任务，查天气、设置闹钟，走 Workflow，稳定低成本。复杂多步任务，行程规划、多文件查询交给 Agent。线上两者混合，减轻大模型压力。

三三面4 题

项目复盘与工程判断，考察对落地瓶颈、动机和长期迭代的思考。

  1. 你的 Demo 上线小米，最大缺陷是什么？重构优先改哪里？

    答Demo 缺少全链路监控与 Trace，没有分级降级，并发能力弱，缺少完整隐私校验。重构优先补全链路追踪、隐私风控、多级降级、badcase 自动收集闭环。

  2. 端云 Agent 最大落地瓶颈是什么？

    答隐私和体验的平衡。全部数据上云有隐私风险；只用端侧模型算力不足，复杂任务效果差。另外弱网场景任务中断，很难续跑。

  3. 为什么投递小米 Agent，不投其他公司 AI 岗位？

    答小米做端云一体的个人助手，和纯云端 Agent 不一样，同时兼顾设备算力、隐私保护，工程挑战很有价值。我想深耕端侧 + 云端协同的 Agent 落地。

  4. 任务指标长期无法提升，你会怎么做？

    答拆解指标定位瓶颈，区分模型、编排、工具、知识库问题，做对照实验迭代。如果提升困难，可以把部分场景切到 Workflow 兜底，不强行全部用 Agent。

四HR 高频5 题

动机、职业规划、挫折冲突与稳定性，明显与「端云协同 / 硬件 + AI」的业务方向绑定。

  1. 自我介绍 + 项目简述

    答我自学大模型与 Agent 开发，用 LangGraph 搭建带 RAG 的智能体 Demo，掌握 RAG、Redis 会话管理、分布式熔断。希望加入小米，参与小爱端云协同 Agent 的落地。

  2. 为什么选小米 Agent 方向？

    答端云协同是小米特色，在硬件 + AI 结合场景做智能助手，我对这个方向很感兴趣，希望在设备端智能体方向持续成长。

  3. 1-3 年职业规划

    答第一年夯实 Agent 应用开发工程能力，熟练 RAG、工具编排；第二年独立负责小型 Agent 模块；第三年深入端云协同场景，参与智能助手产品落地。

  4. 遇到的挫折、团队冲突经历

    答举项目开发例子。项目调试时工具调用频繁死循环，反复排查，最后增加 Redis 熔断和重复行为检测解决。遇到意见分歧，先对齐目标，用实验数据验证方案，而不是主观争论。

  5. 稳定性、到岗时间

    答期望可以稳定长期投入，能满足岗位要求的到岗时间。
